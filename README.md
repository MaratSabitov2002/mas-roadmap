# Агент-помощник методиста

Мультиагентная система генерации образовательных программ. На вход подаётся текстовый запрос и приложенные файлы. Система строит каркас программы (цель, компетенции, часы), а после его утверждения генерирует комплект материалов: РПМ, тесты, семинары, лекции со слайдами и список литературы. Форматы вывода: .docx, .pptx, LMS, JSON.

Документ хранится как граф: часы считаются детерминированно, покрытие компетенций проверяется обходом графа, при правке пересобирается только затронутый подграф. В пайплайне два HITL-гейта: утверждение каркаса и финального черновика.

## Архитектура

```
.
├── README.md              # описание проекта (этот файл)
├── open_webui/            # интерфейс: чат OpenWebUI + панель графа
│   └── README.md
├── knowledge_graph/       # графовая БД: графы документов, версии, diff
│   └── README.md
├── knowledge_base/        # внутренняя БЗ: программы, методички, нормативка
│   └── README.md
└── roadmap-service/       # сервис генерации программ
    ├── README.md
    ├── mas/               # мультиагентная система
    │   ├── README.md
    │   ├── orchestrator/  # сборка всего пайплайна, HITL-гейты
    │   │   ├── README.md
    │   │   ├── pipeline.py    # пайплайн
    │   │   ├── prompts.py     # промпты
    │   │   ├── tools.py       # инструменты
    │   │   └── schemas.py     # Pydantic-схемы
    │   ├── agent1/        # агент (роль уточняется), те же 4 файла + README
    │   └── agent2/        # агент (роль уточняется), те же 4 файла + README
    ├── websearch/         # инструмент поиска в браузере для агентов МАС
    │   └── README.md
    └── attachments/       # инструмент чтения приложенных пользователем документов
        └── README.md
```

> Состав и роли агентов будут уточняться.

> Поиск в браузере — не отдельный сервис, а инструмент МАС (`websearch/`), который агенты подключают через `tools.py`.

## Поток

1. **Запрос** в OpenWebUI → оркестратор.
2. Оркестратор вызывает агентов, которые строят и наполняют граф документа в `knowledge_graph`, опираясь на `knowledge_base`.
3. Каркас программы → **гейт 1** (утверждение методистом).
4. Наполнение комплекта и самопроверка согласованности.
5. Черновик комплекта → **гейт 2** (финальная проверка человеком).
